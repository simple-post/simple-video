# Simple Video

Turn the user’s video request into an editable recipe and a finished local MP4. Run `simple-video --version` first if using an installed CLI. Use `npx --yes --package=@simple-post/video@latest -- simple-video` in place of `simple-video` in the commands below to run the current stable release. An `unknown option` error can mean the installed CLI needs updating.

Use `--json --no-input` for automation. Parse the result on stdout and progress or errors on stderr. A result's `next` or `hint` field suggests the following command; run it with the same invocation. Keep a command's run ID and working directory for resuming.

1. **Choose the layout and shots.** Make routine decisions from the brief. Ask only for missing inputs that change the outcome, such as which files the request refers to. Write concrete image prompts with foreground and background separation, room for captions, and a consistent character or setting. Use short captions the viewer can read at phone size.
2. **Initialize and plan.** Run `init DIR --name "Title"`. For supplied photos add `--photo PATH` once per photo in playback order. For generated images use `--prompt TEXT` once for a single shot or repeat it with `--template slideshow` for 2–12 shots. Optionally add one `--caption TEXT` per shot and `--duration SECONDS` per shot. Comparisons take `--template comparison --hero TEXT --opponent TEXT --setting TEXT`. For per-shot timing, licensed music, or custom rounds, edit the recipe and use `schema --json` to discover fields. Run `--project DIR plan` to check timing, assets and `paidImageRequests`. With `imageSource: "local"`, the files in `localFiles` are what will render. For local comparison photos, map the IDs from that plan in `image.files`.
3. **Resolve setup only if needed.** Use `doctor --runtime-only` to check dependencies without accessing credentials. Add `--check-render` to diagnose graphics failures. If DepthFlow needs installation, inspect `setup --runtime-only --dry-run`, then `setup --runtime-only --yes` once the install is authorized. For generated images, check `auth status`. Use the configured key, or ask the user to enter one in `simple-video auth login` if none is available. Local photos need no key. Keep credentials out of arguments, recipes and chat.
4. **Render and export.** Run `--project DIR create --id STABLE-ID --output EXPORT-DIR`. Image generation is billed to the user's OpenAI account. A request that asks you to create or generate the photos authorizes the plan's `paidImageRequests` within the recipe budget, so add `--execute`. Otherwise, tell the user the request count and `estimatedUsd` and ask before adding `--execute`. Never raise the budget or request more images than the plan without asking. Planning alone leaves generation unexecuted. The result gives `data.export.video`, `data.contactSheet`, timing and media checks. Inspect the sheet and video if available, then give the user the MP4 and recipe paths.
5. **Fix problems using existing photos.** For edge artifacts, lower intensity with `--project DIR render --run STABLE-ID --intensity 0.07`. Export that result with `export --run STABLE-ID --variant VARIANT --output EXPORT-DIR`. Keep the requested duration. Keep motion in one direction within a shot. Use `status --run STABLE-ID` after interruption. Retry an unchanged recipe with the same ID. An ambiguous provider request may already have been billed, so investigate before using `--retry-uncertain`. Use a new run ID when changing the recipe.

Use `COMMAND --help` for exact flags. `init --local` creates original geometric test art for a free demo. For a comparison with a final-round reversal, keep the winner consistent through the preceding rounds and make the result visually readable. Preserve music credits from the export manifest. Send or publish the result only when the user requests it, via a separate tool.
